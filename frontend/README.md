# UniGate Web

Vue 3 + TypeScript + Vite，面向活动负责人、工作人员、校方及参与者。代码由已确认的 33 页 PageSpec 和 OpenAPI 0.3.0 驱动；不是离线名单应用。

## 本地运行

需要 Node.js 22.12 或以上。本项目已在 Node 22.23.3 / npm 10.9.9 上验证。安装使用锁文件和项目 `.npmrc`；后者固定官方 npm registry，并避免 npm 10 的可选 peer 自动解析异常。

```powershell
cd D:\Project\unigate\frontend
npm ci
npm run dev
```

浏览器打开 `http://localhost:5173`。开发服务器把 `/api` 代理到 `http://localhost:8080`，保留浏览器 Origin；后端需允许该开发 Origin，并在本地 HTTP 环境关闭 Secure Cookie。工作人员账号由后端配置，前端没有默认用户名、密码或内置演示名单。

```powershell
npm run typecheck
npm run test
npm run test:coverage
npm run build
```

`npm run build` 已包含类型检查；输出 `dist/`。生产部署使用同源 HTTPS、`/api` 转发与 SPA 路由 fallback；私密 API 响应不得缓存，不引入第三方分析脚本。Android 相机扫码通过 HTTPS/受信任安全上下文使用；普通局域网 HTTP 不能承诺相机权限。系统级 kiosk 锁定及方向锁定需要设备配置。

## 页面与业务操作

- 工作人员登录、首次改密、本人有效授权及终端领取。
- 管理员账号、活动授权、平台连接授权与任务查询。授权活动选择器只读取薄元数据，不获取名单。
- 活动创建及编辑、报名规则、公开报名二维码生成和保存、报名组、首次/增员审核、来源映射、四步名单导入、重复核对及选中行整批提交。
- 检票窗口与终端管理、负责人现场补录/增额、原核销纠错、累计入场统计、受控导出及交付登记、六范围留存清理、通知与后台任务、审计及原操作查询。
- 检票员手机/平板扫描台、辅助找票、本人及本端记录。辅助查找不能把报名组 ID 当作入场码；参与者仍需出示原票，或由负责人核对补发。
- 校方只读统计和后端投影后的获准字段明细，不提供校方导出或编辑入口。
- 公众 H5 按活动策略报名、可选短信、找回私密入口、状态与 QR 入场码、明确保存入场码、按策略自助改随行人数/取消。
- 横屏 kiosk 左侧扫描、右侧确认，默认本次 1 人并显式提交。不展示联系人或名单，提交后只有服务端 `showAsNewAdmission=true` 的新结果显示放行；原结果使用中性提示。成功 5 秒清屏、未提交空闲 30 秒清屏；结果未知不清除操作引用或自动扫描下一组。

列表/表单由专用页面工作区和合同 schema 组合，用户使用中文控件、动态候选、字段分组、可选记录及业务动作，不填写 JSON。服务端权限、活动范围和状态校验为最终依据。

## 合同、凭据与恢复

`src/generated/contract.json` 和 `api-types.ts` 由 `npm run generate:contract` 生成。生成器读取项目正式 OpenAPI/PageSpec，保留源 SHA256、85 个操作和 33 个路由；运行时不用从磁盘外部加载设计文件。只改生成文件会在下次生成时被覆盖。

身份 Cookie 均为后端 HttpOnly Cookie。前端在内存中分别保存匿名、工作人员、本组和设备 CSRF；匿名写与原报名查询使用原 `X-Client-Context-ID`。匿名上下文变化不会自动重发旧报名。刷新后本组写可使用 bootstrap CSRF，但仍需有效的本组/变更 Cookie；这是与后端约定的刷新恢复路径。

未知结果沿用原 `operationId` 与原载荷。浏览器 `sessionStorage` 只保留操作编号、动作、活动、原匿名连续性标记/终端编号，不保留姓名、电话、邮箱、票码、扫描上下文、验证码或完整名单。刷新后不凭“查无记录”另起写入；报名由 RegistrationResult 查询，kiosk 重扫原组后查询，失效/换端交负责人核对。短信、找回、领取在原页面可用原载荷重试；刷新丢失秘密后交工作人员，禁止自动重新提交。

查询/变更 token 由 fragment 读入后立刻清除 URL，再换 HttpOnly Cookie；私密链接只在原提交或恢复成功的内存中可复制。报名/恢复页切换到本组页面通过最长60秒、读取即清除的一次性内存交接，不写浏览器存储。二维码图片保存是参与者显式动作。未实现后台名单缓存或服务工作线程。

## 验证及实际边界

类型检查、生产构建通过；42 个 Vitest 用例通过，覆盖显式入场、防双击、人数范围、超时/处理中/查询/跨端恢复、不重复绿灯、匿名上下文及 CSRF、字段策略/映射、隐私投影、条件必填、时区转换，以及 kiosk 5 秒清屏和 UNKNOWN 40 秒不清屏、改密/创建成功导航及未知时禁止导航。组件测试使用受控 API 响应，不代表 Android 实测、容量压测或真实外部连接器验证。

V8覆盖率由 `npm run test:coverage` 实测：全量源码语句69.00%、分支67.69%、函数64.56%、行87.02%；全部Vue文件合并（含App.vue）语句64.65%、分支65.05%、函数60.96%、行84.58%。不能用高行覆盖率代替语句/函数覆盖，也不能只用components目录75%代替所有页面。仅排除没有运行代码的生成类型别名，未排除任何核心实现；App.vue、main.ts和router.ts的单测覆盖仍为0，保留在分母。完整HTML在 `coverage/index.html`，可归档摘要及源码/测试散列在 `verification/coverage-summary.json`，后者由同一命令自动更新。真实服务浏览器E2E由根目录脚本另行执行，不混入此V8数字。

全局写操作（改密、账号/连接/活动创建）没有活动作用域时不发送必失败的事件结果查询。原页面保留载荷时仅同ID重试；刷新或失去会话时，在无opener的独立登录页由管理员核对，原未知引用保留，不自动重新创建。四步导入在没有批次时从上传或连接来源开始，不要求客户填写批次UUID。来源拉取任务通过正式PULL/SUCCEEDED/resultRef提供“继续名单导入”，query仅携带非秘密批次UUID；导入页先读取本活动BatchDetail的版本及列，再执行预览。上传成功同样定位该query，刷新可恢复批次；权限、有效期和活动归属仍由后端验证。

真实飞书、腾讯文档、邮箱和短信的授权与投递由后端连接器和部署配置决定；前端不会把配置保存或 202 受理显示成已经同步/送达。真机的摄像头朝向、光照、扫码枪、横屏及系统 kiosk 模式需要实际手机/平板验证。公网不可用时停止本端核销；没有 Wi-Fi/蓝牙离线协同。

路由完整清单来自 `src/generated/contract.json` 的 `pages`；合同验证测试保证 33 个路由唯一且操作源完整。
