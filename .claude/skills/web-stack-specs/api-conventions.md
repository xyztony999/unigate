# API 与数据设计规约

## 接口契约

公开业务接口统一前缀 `/api/v1`，后接 `/{domain}/{resource}/{action}`。查询用 GET 或明确说明原因的 POST；写入动作使用 POST。每条接口必须写明方法、完整路径、调用角色、作用域、请求/响应字段与类型、必填/空值、校验、错误及幂等/事务边界。

管理员、设备、参与者私密凭证具有不同身份边界，不共用一个全能令牌。后端校验动作和活动范围，隐藏前端按钮不能代替授权。外部平台的官方 URL 保持原格式，不受本项目路径规则改写。

JSON 用 camelCase，Java 属性与 DTO 对齐；数据库字段用 snake_case。ID 按不透明字符串传输，避免浏览器数值精度和暴露内部序列；编码生成方式由架构决定。时间使用带时区偏移的 ISO 8601，存储策略与活动时区分别定义。人数为非负整数，明确上限、是否含本人和并发规则。

## 响应与错误

统一 JSON 响应为 `{code, message, data, requestId}`，成功 code 为 `OK`；业务错误码为稳定的大写下划线字符串。HTTP 状态表达 400 参数错误、401 未认证、403 无权、404 无资源、409 冲突、422 语义校验、429 限流及 5xx 系统失败。错误不得泄露凭据、完整联系方式或资源存在性。

分页为 `items,total,page,pageSize`，请求页号从 1 开始；每接口明确默认大小、上限和稳定排序。导入批量结果和同步游标另定义，不套用不适合的普通列表分页。枚举统一 `{code,label}`，候选及定稿分别登记公共/业务枚举池；选择器服务入选择服务池。

## 一致性与来源

状态更改写明前置状态和版本条件；幂等标识代表操作而非人员。同一标识同一载荷重试返回已记录结果，不同载荷冲突；作用域、保存时长和持久化位置需定义。并发竞争不依赖前端先查询的结果。

约束校验与事实写入有明确原子边界。审计采用可追溯追加记录，纠错关联原操作；避免静默删除事实。外部来源 ID、批次和更新时间与内部记录 ID 分离，缺少稳定来源 ID 时明确策略。导入错误、部分成功、撤销和后续修改不可含糊处理。

涉及秘密的连接配置由后端管理，返回掩码而非明文；页面、日志、错误、监控和导出均需限定字段。私密查询凭证的能力、有效期、撤销与恢复需写明，扫码凭证不能默认拥有修改报名的权限。

## 规格完整性

每实体定义字段、约束、关系及必要索引；不强制引入与业务无关的公司字段或通用软删除。个人信息实际清理、备份及设备副本处置需单独设计，不能用逻辑删除冒充完成清理。

为关键状态、权限、并发、重试及断网过程写成功与失败示例。每个 PageSpec 字段和动作能追溯到明确 API；可用后台能力与界面可见动作需保持一致。
