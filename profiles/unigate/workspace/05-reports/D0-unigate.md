# UniGate D0 需求澄清报告

日期：2026-10-20；版本：v1.0（阶段状态更新于2026-10-21）；状态：D0完成，ADR-041已确认FL/PRD/领域模型，D1/D2检查通过；D3为待审契约且完整检查未完成。Gate1未执行，无业务代码。下文保留D0形成时的需求记录。

## 输入、来源及匹配

输入为用户对大学见面会体验的描述、既有模型建议及逐轮选择。原工作区无业务架构或接口实现，整体判定为新增；所有概念标注新增，不把早期模型建议当作用户约束。根需求基线 docs/00-intake.md v0.36，完整选择及取代关系见 knowledge/design-decisions/index.md 的 ADR-000—039。

最新明确选择为“首版在线、离线后置”（ADR-039）。此前局域网、Android 主备及公网异常接管需求显式后置，恢复 B 因不适用关闭。历史报告保留研究，不作为首版任务。

## 已确认业务边界

单一主办方自托管、多活动；内置报名与外部名单独立检票两条路径。手机/平板浏览器工作人员及自助 kiosk 在线核销，统一公网服务。独立检票指无需内置报名，仍需访问服务器。首版设计目标单场含随行者 500 人以内、同时 2–5 台设备，尚未实测。

姓名、手机号、邮箱、随行人数四类基础字段按活动启用/必填，不做完整问卷。组名额为 1 加随行人数，缺省随行 0；共用码分批、每名额核销一次，主报名者不必每批在场，不收随行者逐人身份，不记录离场或再入场。

默认立即发码，可开启人工审核；待审核不占额且无有效票，通过时原子占整组，容量不足不通过。自助修改/取消可配置默认关闭，截止不晚于报名截止和现场开始中较早者；已核销后不自助变更。审核模式只审新增差额，保留原批准名额。

现场期间公众报名、审批占额、改人数及取消释放继续冻结；负责人受权加人补录及纠错仍需容量检查和留痕。在线范围变更不自动重开这些入口。

## 角色及对象关系

五角色为系统管理员、活动负责人、检票员、校方只读人员、参与者，可同账号兼任管理员/负责人，平台管理权限不自动授予全部活动明细。查看和导出分权，自助模式仅当前组，完整模块权限在 AA/FL 细化。

活动包含规则、容量、报名组和检票窗口；报名组关联来源、资格、凭证及多条核销事实。导入批次、来源记录、审核决定、通知尝试及审计分别留痕。手机号/邮箱不是普遍唯一键，操作 ID 表示操作而非人员。

## 流程与不变量

完整流程见 D0-flow-draft.md v0.4。报名待审核/有效/拒绝/取消与票证有效性、未/部分/全部入场分开。资格通过原子占整组，核销原子检查剩余名额；取消和纠错不删除已发生事实。

终端不可达时暂停该端，不转本地；超时可能已提交，保留原操作 ID，恢复后查结果或幂等重试，未知结果不能直接显示成功。活动检票窗口与单端网络状态分开，一台掉线不自动暂停全场。结束后核对服务端记录，统计累计核销而非当前在场。

## 集成、通知及数据边界

CSV/XLSX 文件及飞书问卷、腾讯文档 API 首版均需，个人账号先测试并预留组织账号。来源由负责人设有效资格或待审核，仍做字段/容量/来源幂等及疑似重复人工核对；现场新数据不直接生效。真实 API 权限尚未验证，作为实现前验证项登记。

领票私密页面加电子邮件，有效资格方可获有效码，邮件失败不撤销资格，无邮箱仍可页面领取。短信验证可配置默认关闭，开启依赖手机号字段；找票不凭尾号直接补发。

活动及服务端在中国大陆，海外校方需受限明细查看及境内获权导出交付；主体、字段、用途及启用检查后续落实，不实际发送数据。明细默认活动后 30 天可配置，实际清理覆盖受管副本，备份恢复防复活，外部已下载文件另约定。

Java/Spring Boot 与 Vue 已选定；数据库、版本、备份部署及目标浏览器矩阵由架构/详细设计形成具体方案，不从通用栈引入额外微服务中间件。
