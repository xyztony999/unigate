## 关键场景人工复核与修正

| 场景 | 设计结论与证据 |
|---|---|
| 随行与并发最后名额 | 组总数=1+随行；分批扣本次人数，Event→Party锁及版本/余额条件同事务；两端竞争不以先查余额保证成功（API2、数据4） |
| 审核/现场冻结 | READY才普通批准及导入；OPEN/PAUSED公众变更冻结；负责人补录/增额仅OPEN，纠错OPEN/PAUSED，ENDED不自动重开（对应API动作守卫） |
| 超时/处理中/原结果 | UNKNOWN及OPERATION_IN_PROGRESS保留原ID；原成功不重绿灯；固定GATE作用域及设备/组/原版本/人数摘要阻止换目标重扣（API2.3/4.4、交互5/6） |
| 浏览器重启及身份变化 | 只留最小待确认引用；原ANON上下文恢复报名原响应，换cookie不自动套旧ID重发；kiosk重扫原组查旧结果，不恢复离线放行（RegistrationResult、GateOperation） |
| 权限与私密能力 | 管理员无默认名单；检票员无补录/纠错/补发/导出；校方只读无导出；查询/变更/入场能力分离；服务端字段投影及搜索范围一起收缩 |
| 导入冲突 | 预览错误/疑似重复先排除或人工明确；选中集提交全成功或全回滚，同源防重，LINK不改已有名额，外部HTTP不在容量事务内 |
| 通知与导出 | 邮件失败不撤资格；受理≠完成，下载重新鉴权/检查期限；DeliveryRecord只登记，不执行发送 |
| kiosk与清屏 | 无名单搜索，扫码后确认数量；新成功5秒/未提交空闲30秒清屏；未知引用不清，设备失效停止动作；系统kiosk锁定待真机验证 |
| 到期清理 | 到期先归档关闭入口，六范围分别跟踪；物理失败仍禁访问；备份恢复应用删除依据后才开放，不把线上删除当全副本完成 |

本次修正两处表述：PRD4.1原“处置完成后归档”对齐到期先关闭访问；PageSpec中通用“409刷新/确认”细化为按错误code判断，处理中沿原ID等待/查询。均为对齐已采用合同，无新增业务范围；修正后D3/D4及跨阶段检查全部通过。
