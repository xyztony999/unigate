## 五角色入口摘要

- 系统管理员：3 项。账号/角色、平台连接、通用任务状态；无默认活动明细权。
- 活动负责人：23 项。活动规则、来源名单、审核名额、凭证通知、现场控制及异常、统计导出、留存交付和审计。
- 检票员：7 项。获权终端扫码、人数确认、辅助查找、异常转交和原请求结果；无增额、补录、更正、导出或补发。
- 校方只读人员：2 项。获准活动/字段的查看及自身授权范围，不导出或写入。
- 参与者：8 项。本组报名/状态/票、自助变更、找票及受限 kiosk；无名单搜索或设备管理权。

## 本轮新增具体化提案

活动窗口与终端连通分开；原操作超时补查区分重放，避免再次绿灯误导。字段/状态/导出列已形成草稿，业务默认沿用此前确认。误检更正关联原事实、数量受限并审计，不当作离场或再次入场。

来源先预览、标错及提示疑似重复，负责人明确选中要提交的有效行。当前 PRD 建议本次选中行整体提交：如果提交时容量不足或预览过期，本次不产生部分有效票。此处有另一种产品选择，即逐行提交、允许部分成功并明确报告结果。

两种导入方式都不把错误行自动变成有效资格，不按联系方式静默合并、不绕过活动冻结和容量；API 权限仍需真实验证，不以文档存在冒充接通。

## 本轮选择

1. 采用五角色功能清单及产品/领域模型草案，保留“预览后选中行整批提交”（推荐）。据此完成 D1 全局核对、D2 正式完备性/领域建模检查，通过后继续 API 设计。
2. 同样采用上述功能及产品范围，但导入改为“逐行提交，允许部分成功并报告结果”；同步修订 PRD/模型/验收后再进行 D1/D2 检查。

两种选择均不表示 Gate 1 已通过，不包括尚未写出的接口/PageSpec 或实现版本，不授权生成业务代码；所有新状态/字段是当前可审阅设计对象，后续若有实质冲突继续显式说明。
