# UniGate 浏览器页面与检票连接的断网边界

首版适用范围变更：用户选择在线首版（ADR-039），本页的本地页面、PWA 离线和云地切换仅保留为后续研究，首版不实现。浏览器统一访问公网服务，不可达时暂停核销。

日期：2026-10-20；v0.1；来源：用户指出“断网时浏览器网页连接就没了”；状态：技术问题分析及修正提案，用户尚未选择具体入口方案。

## 三种不同的可达性

页面文件来自哪里、核销 API 由谁处理、终端之间是否仍有局域网，是三个独立问题。已打开网页不会仅因断公网而自动消失，但页面刷新、重新打开、懒加载资源和云端 API 都可能失败；普通浏览器缓存不可当作已经验证的离线能力。

Android 热点只能提供网络条件，不能自动把云端网页变成安卓设备上的网页。DNS、证书、身份和有效写入方也不会因连上 Wi-Fi 自动切换。先前只说“双入口并切换”没有把入口何时可达及刷新路径讲清，不能据此宣称浏览器端已可断公网检票。

## 推荐修正提案：本地供页面，正常云端核销

在用户“正常优先连接公网服务器”的要求下，可以将页面供给和业务裁决分开，保留正常公网优先，而不强制页面也只从公网取得。

1. 活动前启动 Android 主设备 App 中的本地 Web 服务，并建立现场热点；浏览器端事先加入同一局域网，打开、验证并保存本地可信 HTTPS 入口。
2. Vue 检票页面、样式、扫码库及所需静态资源由主设备完整提供，现场不依赖 CDN。即使公网已断，主设备和局域网仍正常时，刷新或新开该本地页面也不必从公网取文件。
3. 正常网络下，本地页面优先请求公网核销 API，由云端裁决。该跨源请求需要云端允许精确受信任的本地页面源及正确的授权流程；不得以任意来源 CORS 或泄露长期管理员凭据解决。
4. 公网异常时页面仍可以显示“暂停/等待负责人切换”。负责人按已确认 A1 触发接管，系统证明旧写入方停写、数据完整并处理不确定操作后，该页面才改用主设备的本地 API。
5. 改用哪个 API 的依据是已激活会话及有效写权，不是浏览器一次请求失败。页面能打开不能证明可以放行；普通检票端仍不得独立核销。

这是候选技术路径，不是用户已选定方案。它要求开始时就准备好现场局域网及主设备页面服务；若正常阶段各用各的蜂窝网络，故障时需先加入热点、打开保存的本地入口、恢复终端身份，再完成受控接管，不能称为同一页面无感切换。

## 其他可行方向及边界

- 云端页面加预先准备的 PWA：通过 Service Worker 缓存全部必需资源并验证就绪，可使云端不可达时仍打开应用界面；未预备、缓存丢失或首次使用不能承诺成功。界面缓存不创造可达的本地 API、有效身份或一致数据；公网源访问局域网仍须处理浏览器/OS 权限、CORS、可信入口等。
- 故障时打开独立本地入口：不要求云端页面继续运行，但需要事先保存入口并验证相机与授权，故障时显式导航并恢复待确认操作 ID。不能指望已经断网的云端页面此时才返回重定向地址；公网源存储/登录不自动与本地源共享。
- 原生 Android 检票端：可以内置页面或原生界面与恢复逻辑，但这是附加客户端路径，不能未经用户同意删除首版已确认的浏览器支持。

当前推荐第一节的“本地供页面、正常云端 API 优先”，原因是页面冷打开和刷新不依赖公网，也不把后台数据一致性误归因于 PWA 缓存。仍需按真实设备验证，而非宣称已实现。

## 浏览器及设备限制

本地入口需要受信任且与地址匹配的 HTTPS、可用的本地解析及有效证书链，不能仅给出普通局域网 HTTP 地址就承诺摄像头扫码。Chrome 的本地网络权限因请求来源和版本而异，不能把同一 Wi-Fi 当作权限自动获得。普通热点的域名解析、安卓设备自动离开无互联网 Wi-Fi、蜂窝/热点并用均待验证。

Android 主设备或热点自身故障时，本地页面也可能打不开；这属于主备接管与网络恢复问题，不能用“能断公网”扩展为“任何网络/主设备故障都不中断”。浏览器本地存储仅保留必要未确认操作元数据，并按活动结束/登出清理，不预缓存完整个人名单。

## 验收补充

- 首次活动准备：入口、证书、相机、终端授权及所有静态资源检查通过，再标记浏览器就绪。
- 公网断开、局域网仍在：刷新、关闭后重开、清除普通 HTTP 缓存后从主设备重新加载页面；核销先暂停并保留不确定请求。
- 无预先缓存的浏览器，在已配置可信入口和有效授权条件下，从主设备加载页面，区分“加载成功”和“具备接管核销条件”。
- 浏览器已加载但主设备停机、Wi-Fi 消失或证书失效：明确不能继续，不显示伪成功。
- 云端/本地页面源变化时，不复制旧管理员会话，安全恢复终端身份与原操作 ID，避免重新放行。

## 官方依据

- [W3C Service Workers](https://www.w3.org/TR/service-workers/) 描述请求拦截和缓存用于构建离线 Web 应用；它不是对任意网页默认离线可用的保证。
- [W3C Media Capture and Streams](https://www.w3.org/TR/mediacapture-streams/#navigator-interface-extensions) 将 MediaDevices 入口限定为安全上下文。
- [Chrome Local Network Access](https://developer.chrome.com/blog/local-network-access) 说明局域网访问权限及其来源/地址范围，不能据此推定所有浏览器均可直接跨源连本地服务。

上述方案是基于公开规范的设计推论，无用户设备、实际证书、热点、相机或云端 API 测试。
