# UniGate 首版在线范围评估

日期：2026-10-20；v0.2；状态：用户选择 1，首版在线、离线后置已确认（ADR-039）。下文保留原建议与选项，旧的未确认描述均为提问阶段历史。

## 建议与理由

建议首版要求检票端在线，将局域网离线检票列为后续能力。已确认目标是单场 500 人以内、2–5 台设备；真实产品价值仍包括简化报名、外部名单导入、随行组码分批核销及统计。在线首版可以用单一服务器事务保证多人同时检票时的剩余名额，先验证完整业务流程及现场体验。

作为产品先例，pretixSCAN 官方同时提供 online-only/no-order-sync 配置，并明确该配置不能离线扫描；它的存在说明在线与离线可作为分开的能力范围，但不能据此保证 UniGate 的特定场地网络可靠。[pretixSCAN 官方说明](https://docs.pretix.eu/guides/pretixscan/android/#connecting-the-device-to-the-pretix-backend)

## “扫码”和“联网”需区分

扫码识别二维码本身不必联网。参与者可以展示事先保存的入场码，由联网的工作人员端验证；不要求参与者现场打开微信网页、重新填表或保持自己的手机联网。报名与重新打开在线领票页需要相应服务可达，不把“之前微信扫码”当成场地网络保证。

纯在线模式要求实际提交核销的设备能访问公网服务器；Wi-Fi 和移动网络切换可以改善可用性，但服务器故障、全网不可达仍会使核销暂停。人数规模是范围评估依据，不是网络质量或服务可用性证明。

## 如果选择在线首版，拟调整的实现范围

- 管理后台、报名/领票和手机/平板浏览器检票通过 Vue Web 访问同一公网 Spring Boot 后端。
- 首版不再需要 Android 主/备协调设备、本地 Web 服务器、局域网证书与本地 DNS、云地写权转移及离线日志同步。安卓手机/平板继续作为正常检票终端；操作系统 kiosk 锁定与浏览器兼容性仍需验证，不能宣称全屏已经锁住设备。
- 保留所有业务资格、容量、组名额、分批、审核、来源冲突、通知、权限及数据生命周期规则。现场公众报名变更是否继续冻结按现有确认保留，不从改成在线自动推定重开。
- 服务器做原子核销及权限校验；超时显示结果待确认，重试沿用同一操作 ID 并查询结果，不能视为未入场再发新核销。请求成功但回包丢失的问题在线模式也存在。
- 网络不可用时系统核销暂停，不能缓存为成功或自动宽松放行。现场准备可切换的 Wi-Fi/移动网络；若需要人工应急，由负责人制定名单、人数及事后核对规则，作为显式业务例外，不能冒充系统已完成核销。
- 保留设备/操作标识、服务边界等普通可扩展契约；不为未来离线提前实现整套主备和同步协议，不承诺未来加离线无需重构。

## 当前选择

1. 首版在线检票，离线能力后置（推荐）。正常检票设备必须能访问服务器；断网暂停并恢复网络，不开发自动或手动局域网接管。
2. 首版仍保留断公网检票：继续 Android 主备、浏览器本地入口、数据同步和单写权设计，接受实现与现场准备的额外工作。

用户已选择 1。离线相关首版要求按 ADR-039 明确后置，旧 ADR 不删除；同步 BA/AA/流程，现场准备、在线暂停与恢复替代主备交接活动，保留原业务层级 ID 以便追溯。

公网恢复策略 B 因在线首版不再适用而关闭，不推定用户选过 B1 或 B2。
