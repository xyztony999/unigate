## 角色范围

- 系统管理员：部署配置、账号停用/启用及平台连接凭据；不因管理员角色自动提供全部活动明细查询。测试中可与负责人由同账号兼任，但仍记录具体活动操作人。部署权限能接触基础设施的边界单独说明。
- 活动负责人：仅管理获授权活动。配置、导入、来源资格、审核、统计及获授权导出；现场通过有效主设备办理加人、补录、暂停及接管。建议误检纠错和凭证撤销/补发同样仅负责人，需理由及审计。
- 检票员：仅获授权活动与终端。扫码、确认本次人数、核销、查询自己的操作结果及辅助找报名；查询按需、敏感字段最小展示，不可浏览/导出全部名单，不可加人补录或改容量。
- 校方只读人员：仅获授权活动、字段和有效期内查看数据，断公网时云端数据显示同步时间；不审批、不检票、不增额。明细查看和导出分权；当前需求中的文件交付由境内获授权负责人发起，不额外授予校方读者导出权。
- 参与者：内置报名者或外部名单持票组，通过私密凭证访问本组；按活动配置和窗口修改/取消。组码仅证明可尝试核销，不授予修改报名或搜索名单的权限。

现场期间公众报名等变更保持冻结，正常核销由公网处理，接管后负责人不能用管理后台绕过本地写入权。管理员停用或撤权在离线端的生效延迟必须在授权包有效期、重新连接检查和紧急现场撤权流程中定义，不能承诺公网断开时云端撤权瞬时生效。

## 终端范围

- 云端管理与报名/领票：Vue Web，Spring Boot 后端，按活动权限及凭证分开校验。
- Android 主设备：正常优先使用公网检票并准备可接管数据；异常受控接管后提供现场权威核销、统计和负责人操作，可附带扫码端。
- Android 备用设备：预配对及数据准备，受控接管前不写入核销。
- 其他 Android 或浏览器检票端：正常连接公网服务，受控接管后连接有效 Android 主设备；只向当前有效裁决方提交，不各自承担离线名额裁决。浏览器首轮验证建议 Android Chrome、Windows Chrome/Edge，尚未固定全部平台清单。
- 自助 kiosk：受限终端模式，只处理当前组码和本次人数，不开放名单搜索；固定设备或操作系统锁定单独验证。

Android 本地服务的实现不应被误读为在手机上运行完整 Spring Boot 云端部署；如何共享规则、测试及数据契约留给技术设计。Vue 可用于浏览器检票页面，Android 原生或嵌入页面方案尚未锁定。

## 已确认业务层级摘要

完整 L2/L3/L4 见 ../00-architecture/business-arch.md。四阶段、八项关键业务及十七项活动建议如下：

1. 筹备：活动规则设定 → 活动基础信息设定、报名及留存规则设定。
2. 报名与名单准备：报名及名单接收 → 内置报名接收、外部名单接收与核对；资格与名额管理 → 资格审核与名额确认、报名人数变更与取消；凭证交付 → 状态查询与领票、邮件通知与找票协助。
3. 现场入场：现场准备与交接 → 名单交接与现场开启、暂停/接管/恢复；入场核销与异常处置 → 组码识别及分批核销、现场增额及补录、无效凭证/重复/误检处理。
4. 收尾与留存：结果统计与交付 → 现场封存与结果核对、统计查看与明细交付；留存与清理 → 明细到期处置、外部副本处置记录。

业务架构只描述业务，角色与实现范围由本文说明，后续 AA/FL 引用相同 ID 与层级。BA 层级已确认；AA 候选已生成，模块角色及调用仍须确认，不表示 D1 或 Gate 1 通过。
