# UniGate 应用架构

| 属性 | 值 |
|---|---|
| 版本 | v0.5 |
| 状态 | ADR-047 领域重划分已采纳；模块 8+3→6+3，AA 叶 23 不变 |
| 日期 | 2026-11-11 |

ADR-040/041 确认的在线 AA（8 业务+3 平台模块）经 ADR-047 按实现证据重划：资格与名额管理并入凭证交付组成「资格、名额与凭证」，现场准备与控制并入入场核销组成「现场检票与控制」，连接与任务拆为「外部连接」与「平台运行」。业务子模块 17 个、平台子模块 6 个（AA 叶 23）、五角色及调用边界语义不变；编号与调用关系按新结构重排，FL/API 已同步重挂。

## 第一部分：文档概述

### 1.1 背景与目标

将 BA v0.5（4 阶段/6 关键业务/17 活动）映射为在线首版功能组织（ADR-039/047）；所有核销由公网服务裁决，离线和 Android 主备后置。业务规则和五角色保持。

### 1.2 文档定位

本文定义应用域、功能模块、子模块、涉及角色与调用。在线范围见 ../05-reports/online-first-scope-review.md 与 ADR-039；重划分依据与实现取证见 ../05-reports/domain-redivision-proposal.md 与 ADR-047。接口和页面在 D3/D4 定义。模块调用是逻辑依赖，不表示拆成微服务或通过远程接口逐次调用。

### 1.3 范围

单一主办方多活动，五类角色，手机/平板浏览器检票端及自助 kiosk 模式；不扩展公共多租户。平台模块是支撑既有功能的技术能力，不追加业务需求。

## 第二部分：应用架构

### 本架构概览

核心业务域管理资格凭证、在线检票控制及核销（两大不变量：名额占用、核销唯一性）；支撑业务域组织规则、名单接入、统计交付和留存；基础数据域本期不设独立维护模块；平台支撑域提供身份授权、外部连接与平台运行（任务/幂等/审计）。全部 BA L3/L4 覆盖不变。

### 应用域分层

| 分层 | 说明 | 功能模块 |
|---|---|---|
| 核心业务域 | 持有关键状态与名额不变量 | 资格、名额与凭证；现场检票与控制 |
| 支撑业务域 | 支撑核心流程的业务规则 | 活动规则设定；报名及名单接入；结果统计与交付；留存与清理 |
| 基础数据域 | 代码及枚举等引用数据 | 无独立业务维护模块；在公共规约维护统一编码 |
| 平台支撑域 | 不含业务裁决的通用能力 | 身份与授权；外部连接；平台运行 |

### 2.1 核心业务域

**应用域概述**：管理有效资格、凭证、剩余名额和统一在线核销窗口，服务负责人、检票员及参与者。

#### 2.1.1 资格、名额与凭证

**功能说明**：覆盖 BA 2.2.2；组织资格审核、名额确认、变更取消及凭证交付的全部活动（ADR-047 合并原「资格与名额管理」与「凭证交付」）。

**涉及用户类型**：- [ ] 系统管理员 - [✓] 活动负责人 - [✓] 检票员 - [ ] 校方只读人员 - [✓] 参与者

##### 2.1.1.1 资格审核与名额确认

**功能说明**：立即生效及已获资格来源需通过字段和容量检查；待审核不占额，通过时才占用整组名额，容量不足不能通过。 追溯 BA 2.2.2.1。

**涉及用户类型**：- [ ] 系统管理员 - [✓] 活动负责人 - [ ] 检票员 - [ ] 校方只读人员 - [ ] 参与者

**调用关系**：支撑业务域/活动规则设定：校验容量与审核策略；核心业务域/现场检票与控制：检查活动阶段和变更窗口；平台支撑域/平台运行：保留决定。

##### 2.1.1.2 报名人数变更与取消

**功能说明**：按活动开关、截止与核销状态处理人数变更或取消，审核增员只审核差额并保留原批准名额；现场仅负责人办理受权调整。 追溯 BA 2.2.2.2。

**涉及用户类型**：- [ ] 系统管理员 - [✓] 活动负责人 - [ ] 检票员 - [ ] 校方只读人员 - [✓] 参与者

**调用关系**：支撑业务域/活动规则设定：校验容量与审核策略；核心业务域/现场检票与控制：检查活动阶段和变更窗口；平台支撑域/平台运行：保留决定。

##### 2.1.1.3 状态查询与领票

**功能说明**：通过私密页面查看本组状态，有效资格方可领取有效组码，待审核及被拒绝不得以查询链接绕过资格。 追溯 BA 2.2.2.3。

**涉及用户类型**：- [ ] 系统管理员 - [✓] 活动负责人 - [ ] 检票员 - [ ] 校方只读人员 - [✓] 参与者

**调用关系**：平台支撑域/身份与授权：校验本组能力；平台支撑域/平台运行：投递通知任务。

##### 2.1.1.4 邮件通知与找票协助

**功能说明**：有可用邮箱时支持通知，投递失败不撤销资格；缺少邮箱仍保留页面领票。链接丢失和外部名单的找票方式在规格中明确。 追溯 BA 2.2.2.4。

**涉及用户类型**：- [ ] 系统管理员 - [✓] 活动负责人 - [✓] 检票员 - [ ] 校方只读人员 - [✓] 参与者

**调用关系**：平台支撑域/身份与授权：校验本组能力；平台支撑域/平台运行：投递通知任务。

#### 2.1.2 现场检票与控制

**功能说明**：覆盖 BA 2.3.1；组织现场会话的开启控制、核销及异常处置（ADR-047 合并原「现场准备与控制」与「入场核销与异常处置」）。

**涉及用户类型**：- [ ] 系统管理员 - [✓] 活动负责人 - [✓] 检票员 - [ ] 校方只读人员 - [✓] 参与者

##### 2.1.2.1 现场就绪与开启

**功能说明**：核对有效名单、检票权限及服务可达性，停止公众报名等影响资格与名额的后台变更，再开启在线检票；第三方新增答卷不得直接增加现场有效名额。 追溯 BA 2.3.1.1。

**涉及用户类型**：- [ ] 系统管理员 - [✓] 活动负责人 - [ ] 检票员 - [ ] 校方只读人员 - [ ] 参与者

**调用关系**：核心业务域/资格、名额与凭证：取得一致的有效名额；平台支撑域/身份与授权：验证负责人和设备；平台支撑域/平台运行：记录现场开启与暂停状态。

##### 2.1.2.2 暂停与恢复

**功能说明**：断网或服务异常时暂停核销，恢复可达后核对原操作结果再继续；不向本地转移名额裁决，不把未知结果视为未入场。 追溯 BA 2.3.1.2。

**涉及用户类型**：- [ ] 系统管理员 - [✓] 活动负责人 - [ ] 检票员 - [ ] 校方只读人员 - [ ] 参与者

**调用关系**：核心业务域/资格、名额与凭证：取得一致的有效名额；平台支撑域/身份与授权：验证负责人和设备；平台支撑域/平台运行：记录现场开启与暂停状态。

##### 2.1.2.3 组码识别及分批核销

**功能说明**：凭组码确认本次入场人数，在剩余名额内核销；每个名额只核销一次，不由人数推断自然人身份，不登记离场。 追溯 BA 2.3.1.3。

**涉及用户类型**：- [ ] 系统管理员 - [✓] 活动负责人 - [✓] 检票员 - [ ] 校方只读人员 - [✓] 参与者

**调用关系**：核心业务域/资格、名额与凭证：校验并占用剩余名额；平台支撑域/平台运行：持久化事实。

##### 2.1.2.4 现场增额及补录

**功能说明**：容量允许时受控办理加人和未报名补录，名额分配与实际核销分别记录。 追溯 BA 2.3.1.4。

**涉及用户类型**：- [ ] 系统管理员 - [✓] 活动负责人 - [ ] 检票员 - [ ] 校方只读人员 - [ ] 参与者

**调用关系**：核心业务域/资格、名额与凭证：校验并占用剩余名额；平台支撑域/平台运行：持久化事实。

##### 2.1.2.5 无效凭证、重复及误检处理

**功能说明**：对无效、剩余不足、重复操作和误检提供核对处置；纠错保留原入场事实及关联更正依据，不作为再次入场机制。具体纠错边界待规格审阅。 追溯 BA 2.3.1.5。

**涉及用户类型**：- [ ] 系统管理员 - [✓] 活动负责人 - [✓] 检票员 - [ ] 校方只读人员 - [ ] 参与者

**调用关系**：核心业务域/资格、名额与凭证：校验并占用剩余名额；平台支撑域/平台运行：持久化事实。

### 2.2 支撑业务域

**应用域概述**：提供规则、名单接入、凭证以外的结果使用及留存，按活动和角色限定范围。

##### 2.2.1.1 活动基础信息设定

**功能说明**：登记活动名称、时间及容量，容量按含随行者的总人数计算；每场容量单独设定。 追溯 BA 2.1.1.1。

**涉及用户类型**：- [ ] 系统管理员 - [✓] 活动负责人 - [ ] 检票员 - [ ] 校方只读人员 - [ ] 参与者

**调用关系**：平台支撑域/身份与授权、平台支撑域/平台运行：校验活动范围并留痕。

##### 2.2.1.2 报名及留存规则设定

**功能说明**：设定四项基础字段、立即发码或审核后发码、可选手机号验证、自助修改取消和明细保留期限，期限默认活动结束后 30 天。 追溯 BA 2.1.1.2。

**功能说明**：覆盖 BA 2.4.1；组织结果核对、统计与受控交付。

### 2.3 基础数据域

**应用域概述**：本期没有独立业务模块。公共/业务枚举和引用编码随契约维护，不新增通用字典管理菜单。

### 2.4 平台支撑域

**应用域概述**：通用基础能力，所有业务动作仍由上层状态、容量及权限约束。后台任务为技术执行主体，不是第六种业务用户。ADR-047 将原「连接与任务」拆为「外部连接」（凭据保管）与「平台运行」（任务/幂等/审计），与实现的表属主一致。

#### 2.4.1 身份与授权

**功能说明**：为现有业务提供可复用基础能力，无 BA 新增业务活动。

**涉及用户类型**：- [✓] 系统管理员 - [✓] 活动负责人 - [✓] 检票员 - [✓] 校方只读人员 - [✓] 参与者

##### 2.4.1.1 账号与活动授权

**功能说明**：按角色、活动、字段和动作校验身份；管理员不自动取得全量活动明细。

**涉及用户类型**：- [✓] 系统管理员 - [✓] 活动负责人 - [✓] 检票员 - [✓] 校方只读人员 - [✓] 参与者

**调用关系**：由业务模块调用；基础能力间仅依赖身份验证及通用持久化，不反向发起业务核销或名额分配。

##### 2.4.1.2 终端绑定与会话

**功能说明**：限制已配对终端及本组凭证的能力，支持受控失效与重新绑定。

**涉及用户类型**：- [ ] 系统管理员 - [✓] 活动负责人 - [✓] 检票员 - [ ] 校方只读人员 - [✓] 参与者

**调用关系**：由业务模块调用；基础能力间仅依赖身份验证及通用持久化，不反向发起业务核销或名额分配。

#### 2.4.2 外部连接

**功能说明**：为现有业务提供可复用基础能力，无 BA 新增业务活动。原「连接与任务」的凭据保管部分。

**涉及用户类型**：- [✓] 系统管理员 - [ ] 活动负责人 - [ ] 检票员 - [ ] 校方只读人员 - [ ] 参与者

##### 2.4.2.1 连接凭据保管

**功能说明**：保管第三方和通知连接凭据，业务页面仅引用被授权连接。

**涉及用户类型**：- [✓] 系统管理员 - [ ] 活动负责人 - [ ] 检票员 - [ ] 校方只读人员 - [ ] 参与者

**调用关系**：由业务模块调用；基础能力间仅依赖身份验证及通用持久化，不反向发起业务核销或名额分配。

**功能说明**：为现有业务提供可复用基础能力，无 BA 新增业务活动。承接原「连接与任务」的任务执行与原「审计与执行」的幂等/审计。

## 第三部分：应用架构树

由第二部分节点对应生成；业务节点完整映射 BA，平台节点为技术补充。

```text
UniGate
├── 核心业务域
│   ├── 资格、名额与凭证
│   │   ├── 资格审核与名额确认 — 立即生效及已获资格来源需通过字段和容量检查；待审核不占额，通过时才占用整组名额，容量不足不能通过。
│   │   ├── 报名人数变更与取消 — 按活动开关、截止与核销状态处理人数变更或取消，审核增员只审核差额并保留原批准名额；现场仅负责人办理受权调整。
│   │   ├── 状态查询与领票 — 通过私密页面查看本组状态，有效资格方可领取有效组码，待审核及被拒绝不得以查询链接绕过资格。
│   │   └── 邮件通知与找票协助 — 有可用邮箱时支持通知，投递失败不撤销资格；缺少邮箱仍保留页面领票。
│   └── 现场检票与控制
│       ├── 现场就绪与开启 — 核对有效名单、检票权限及服务可达性，停止公众报名等影响资格与名额的后台变更，再开启在线检票。
│       ├── 暂停与恢复 — 断网或服务异常时暂停核销，恢复可达后核对原操作结果再继续；不向本地转移名额裁决。
│       ├── 组码识别及分批核销 — 凭组码确认本次入场人数，在剩余名额内核销；每个名额只核销一次，不登记离场。
│       ├── 现场增额及补录 — 容量允许时受控办理加人和未报名补录，名额分配与实际核销分别记录。
│       └── 无效凭证、重复及误检处理 — 对无效、剩余不足、重复操作和误检提供核对处置；纠错保留原入场事实及关联更正依据。
├── 支撑业务域
│   ├── 活动规则设定
│   │   ├── 活动基础信息设定 — 登记活动名称、时间及容量，容量按含随行者的总人数计算。
│   │   └── 报名及留存规则设定 — 设定四项基础字段、发码模式、可选手机号验证、自助修改取消和明细保留期限。
│   ├── 报名及名单接入
│   │   ├── 内置报名接收 — 按活动规则接收基础信息和随行人数，不要求建立长期参与者账号。
│   │   └── 外部名单接收与核对 — 接收文件及飞书问卷、腾讯文档来源，完成字段对应、来源记录核对和异常处理。
│   ├── 结果统计与交付
│   │   ├── 现场封存与结果核对 — 结束检票时停止现场变更，核对服务端完整记录和更正依据。
│   │   └── 统计查看与明细交付 — 区分组数、有效名额和累计入场数；明细查看与导出分别控制。
│   └── 留存与清理
│       ├── 明细到期处置 — 到期清理受管明细及中间副本，使私密查询失效。
│       └── 外部副本处置记录 — 登记明细交付范围及接收方保存责任。
├── 基础数据域
│   └── 本期无独立功能模块
└── 平台支撑域
    ├── 身份与授权
    │   ├── 账号与活动授权 — 按角色、活动、字段和动作校验身份；管理员不自动取得全量活动明细。
    │   └── 终端绑定与会话 — 限制已配对终端及本组凭证的能力，支持受控失效与重新绑定。
    ├── 外部连接
    │   └── 连接凭据保管 — 保管第三方和通知连接凭据，业务页面仅引用被授权连接。
    └── 平台运行
        ├── 任务与队列管理 — 执行已授权的平台读取、通知及生命周期任务，失败与业务资格分开。
        ├── 操作幂等与结果查询 — 提供同一操作 ID 的重试及结果查询；按角色限范围，不把超时视为失败。
        └── 操作事实持久化 — 提供有范围的追加事实及结果查询，业务规则由对应业务模块决定。
```

## 附录

### 角色与调用边界

- 勾选表示该角色参与该能力，不表示拥有子模块内全部动作；检票员找票只辅助查找，凭证撤销/补发和误检纠错由负责人。
- 校方只读参与统计查看，不取得导出动作；参与者只在本组及活动允许窗口操作，kiosk 无名单搜索。
- 核销与名额始终由统一在线服务处理，浏览器不能独立离线放行；网络恢复后先查询未知结果。
- 通知、清理和连接任务通过系统身份执行，角色标注用于配置和查看执行结果；不能据此让参与者执行任意任务。
- 检票员的审计/结果查询仅限获准操作范围，不开放全量日志或个人明细；管理员保管凭据不取得业务查询权。
