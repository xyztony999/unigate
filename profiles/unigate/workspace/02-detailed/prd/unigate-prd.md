# UniGate 在线首版产品需求

日期：2026-10-21；版本：v1.0（需求/模型基线2026-10-20，阶段注记更新于2026-10-21）；状态：需求由ADR-041确认，D2归档；ADR-043后D3按项目依据完成，ADR-044确认D4；独立Gate1结论见05-reports/gate1-unigate-2026-10-21.md。

## 1. 目标、范围及依据

为大学新生/家长见面会等活动提供简洁报名、外部名单接入、组码分批检票及统计，减少参与者现场重新填写资料。主办方自托管、多场活动，首版单场含随行者 500 人以内、同时 2–5 台检票设备为设计目标，不是实测性能或系统记录数上限。

业务依据 ADR-001—040，后项覆盖前项冲突；首版仅在线（ADR-039）。BA v0.3、AA v0.3 与 function-list.md v0.1 位于 ../../00-architecture/，D0 基线位于 ../../05-reports/D0-flow-draft.md。本稿的状态、字段、批次原子边界和验收已由 ADR-041 确认，精确接口合同在 D3 设计，业务既定规则不因这些提案改变。

包含内置报名、CSV/XLSX、飞书问卷和腾讯文档 API、审核、差额增员、页面/邮件领票、工作人员及 kiosk、现场负责人补录、统计导出、权限及明细清理。首版不含离线核销、Android 主备、本地 Web/API、云地切换、收费售票、公共多租户、完整问卷编辑器、随行者逐人身份、离场和再次入场。

## 2. 用户与入口

系统管理员配置账号、角色和连接，不自动读取全部活动明细；活动负责人管理获准活动及现场异常；检票员找票、扫码、确认人数及查询获准操作；校方只读人员按活动/字段/期限查看，无导出或写入；参与者仅本组报名、状态、票和获准自助动作。相同账号可兼任管理员/负责人，仍按明确授权校验。

详细入口及功能以 FL 为准，以下是产品组织摘要：

- 管理员：账号与角色、平台连接配置、连接与任务状态。
- 负责人：活动管理、报名设置、名单导入及平台来源、审核待办、报名/领票管理、检票控制与设备、工作人员检票、现场补录/异常纠错、统计/导出、留存/交付记录和审计。
- 检票员：授权活动与终端就绪、工作人员检票、辅助找票、异常转交、本端操作及待确认结果。
- 校方只读人员：我的授权范围、活动统计及获准字段明细。
- 参与者：活动报名、我的报名、状态/入场码、通知/找票；在 kiosk 使用本组组码和人数，不搜索名单。

业务动作统一服务端鉴权；前端隐藏按钮只是展示。终端身份、工作人员账号与参与者能力凭证分开；参与者不强制长期账号。

## 3. 领域对象及字段提案

ID 使用不透明字符串，时间为带时区偏移的 ISO 8601 表达，人数为整数。数据库与接口的最终精确 DTO/索引在 D3 锁定，本节提供需求级字段，枚举以 code+label 形式传输。

| 对象 | 关键字段 | 约束及关系 |
|---|---|---|
| 活动 Event | id、title、venue、startsAt、endsAt、timeZone、registrationStartsAt、registrationEndsAt、capacity、status、version | title/时间/时区/容量必需，结束不早于开始；capacity>=1 且降低后不小于已占名额；同部署多活动；不以 500 作为固定容量 |
| 活动策略 EventPolicy | 四字段 enabled/required、approvalMode、phoneVerificationEnabled、selfEditEnabled、selfCancelEnabled、selfServiceEndsAt、retentionDays | 默认即发、短信关闭、自助修改/取消关闭、保留 30 天；required 必须 enabled；短信开启须手机号并验证；自助截止不晚于报名截止和检票开始 |
| 报名组 RegistrationParty | id、eventId、name?、phone?、email?、companionCount、approvedSize、pendingIncrease?、status、sourceType、version | 基础字段遵循策略；随行缺省 0，总申请数=1+随行；有效已批准数与待审核新增差额分开；联系方式不是唯一人员标识 |
| 资格决定 EligibilityDecision | id、partyId、kind、requestedSize、approvedIncrease?、result、reason、actorId、decidedAt | 首次及新增差额分别留痕；待审核不占额，批准原子校验；拒绝说明原因，不自动建立候补 |
| 来源连接 SourceConnection | id、provider、accountKind、authorizationStatus、credentialRef、resourceRef | provider 为飞书/腾讯等；个人测试保留组织身份；秘密只在服务端，负责人只选获准连接/资源 |
| 导入批次 ImportBatch | id、eventId、sourceRef、fileDigest?、mapping、sourceEligibility、status、previewVersion、rowResults | 来源资格为已获资格/待审核；预览与提交分开，映射和活动规则变化导致预览过期；实际权限失败不显示接通成功 |
| 来源关联 SourceLink | id、partyId、connectionId?、resourceId?、sourceRecordId?、batchId、sourceUpdatedAt? | 稳定同源 ID 幂等；一组可保留多个经核对关联；缺 ID 文件重传与跨源疑似重复不能按手机号静默合并 |
| 入场凭证 AdmissionCredential | id、partyId、tokenDigest、version、status、issuedAt、expiresAt | 有效资格才有有效票，二维码无明文联系方式；撤销/补发失效旧票但不增加名额；状态页/变更凭证与组码能力分离 |
| 检票操作 CheckInOperation | id、eventId、partyId、deviceId、actorType、actorId?、operationId、requestedCount、requestDigest、result、committedAt? | count>=1；同一操作 ID 同载荷返回原结果、异载荷冲突；只有提交成功才产生核销事实；未知是客户端状态，不等同于服务端失败 |
| 核销事实及更正 AdmissionRecord/Correction | id、operationId、partyId、admittedCount、originalRecordId?、correctedCount?、reason?、actorId、recordedAt | 事实追加，更正关联原事实；纠错仅负责人；不删除历史，不当作离场释放名额 |
| 终端会话 DeviceSession | id、eventId、mode、status、authorizedBy、expiresAt | 工作人员/kiosk 分离，绑定活动，服务器撤权校验；kiosk 管理解锁与参与者组码分离 |
| 通知/导出/清理任务 | id、eventId、kind、status、attempts、resultRef?、expiresAt? | 与资格独立；包含邮件投递、导出文件、到期清理等过程，不把任务成功混为报名或核销成功 |
| 活动授权 EventGrant | id、accountId、eventId、role、allowedFields、allowedActions、expiresAt | 限活动、字段、动作和期限；查看不含导出，负责人不能授予超出自身范围的权能 |

## 4. 已确认状态及转换

### 4.1 活动阶段

状态：DRAFT（草稿）、READY（已发布/准备）、CHECKIN_OPEN（检票开放）、CHECKIN_PAUSED（检票暂停）、ENDED（已结束）、ARCHIVED（明细清理归档）。DRAFT 校验配置后到 READY；负责人 READY→CHECKIN_OPEN 时原子冻结公众报名等变更并处理在途操作；OPEN↔PAUSED 仅负责人；OPEN/PAUSED→ENDED 停止普通现场写入；明细到期先转ARCHIVED并失效访问、冻结写入，再执行实际清理。ARCHIVED不代表所有副本已删除；清理状态及六范围进度独立，物理失败仍不可访问。

报名是否可提交同时受 READY、报名开关/时间及容量限制；审核活动不因尚有待审核申请自动占额。单台终端断网只是其本地连通状态，不把活动自动改成 PAUSED。ENDED 不因恢复网络重开，具体活动重启不列为本稿默认功能。

### 4.2 报名资格与增员

PENDING（待审核）→APPROVED（已批准）/REJECTED（已拒绝）/CANCELLED（已取消）。即发模式或有效来源可直接 APPROVED，但必须通过字段与容量；PENDING 不发有效票。允许窗口内且无核销的 APPROVED 可取消并释放占额。

有效组增员时原 APPROVED 资格保留，pendingIncrease 单独决定，通过时原子占差额，不足保持待处理且不增加有效票额。有效减少释放差额，不能减少至已核销数以下；参与者已有核销后整个自助变更入口关闭。现场普通审批变更冻结，现场增额/补录必须走独立负责人动作，不能借审核 API 绕过。

拒绝后重新提交需要新申请或显式重开并留关联，不覆盖原决定。本稿建议首版用新申请，不能因重新提交免审核或自动合并。

### 4.3 凭证、进度及操作

凭证状态 ACTIVE/REVOKED/EXPIRED；待审核无有效票。活动结束后停止核销，状态/明细查询仍在获准期限内，清理到期后凭证与私密查询失效。

入场进度根据有效名额 N 和净核销 C 计算：C=0 为未入场，0<C<N 为部分，C=N 为全部；0<=C<=N，不识别独立自然人。资格不是进度，不因第一次扫码就整组到场。

操作状态 IN_PROGRESS/SUCCEEDED/REJECTED，客户端另有 RESULT_UNKNOWN。若服务端未查到原 ID，仍以相同 ID 查询/重试，不据一次查无记录另发新操作。同 ID 不同载荷冲突，明确失败后用户主动调整人数再提交才是新操作。正式保存期限、结果字段与错误码在 D3 定义。

## 5. 核心场景与边界

### 5.1 发布及内置报名

负责人设置活动与基础策略，检查容量、时间、字段依赖、发码和通知。参与者看到活动信息、所收字段用途、保留期和必要告知；提交按规则校验。即发模式成功占额并展示保存入口/票；审核模式仅显示待审核且说明未预留名额。邮件另行投递，失败不撤销资格。

仅收一个组的基础信息与随行人数；未收手机/邮箱仍能用成功页面的私密入口。参与者可以保存二维码截图，由联网的工作人员/kiosk 验证；不强制每人现场微信打开网页或重填资料。

### 5.2 文件/API 名单接入

负责人选授权连接/文件→活动及资源→字段映射→来源资格→预览错误/重复→明确选中有效行→确认提交→结果。API 作为后台接入任务执行，飞书与腾讯个人账号的真实开发者/应用/文档权限必须实现前验证；文件路径不能用来虚报 API 已完成。

已确认批次语义：预览可排除错误行，提交时对本次明确选中行整体事务校验；来源重传不新增，剩余选中行的有效资格占额总和必须容量允许，否则本次不产生新的有效名额，重新预览处理。待审核来源只创建申请，不占容量。映射、规则或来源数据版本变化导致预览过期，不能用旧确认覆盖新名单。

同源稳定 ID 复用关联；无稳定 ID 的文件以活动/来源/文件摘要/映射指纹识别完全重传，不能据文件名或联系方式保证同人。跨来源疑似重复先保留来源并隔离待核对，负责人决定关联或分别保留，决策留痕。后续源端改动作为待处理差异，不直接覆盖已批准/已核销记录。

字段映射：姓名/联系方式取字符串并去首尾空白，保留可追溯原值；手机号保留国家区号、按配置校验而非强制转为中国大陆 11 位；邮箱不作为唯一键，不能把缺失邮箱变成必填。随行人数为空按活动缺省 0，负数、小数、非数字及超活动规则范围的值进入行错误；平台“总人数”字段须显式映射并换算为随行=总数减 1，不能把总数再次加本人。未收字段不强制导入，时间及来源 ID 用明确类型解析，未知额外列不自动成为新问卷字段。实际飞书/腾讯结构从获权资源样例核实后绑定，不从中文表头猜测 API 字段。

### 5.3 审核及名额

负责人按申请/增员类型审核，显示申请人数、已批准数和当前可用容量。批准决定与容量更新同一事务；并发最后名额只允许容量内的结果成功。不足不拆组、不自动候补、不把业务冲突变成成功。拒绝留理由，待处理的申请不提供有效票。

### 5.4 工作人员检票

登录获准活动/终端，检查公网与相机；扫描组码或最小范围找票→资格与剩余名额→确认本次人数→提交→明确服务端成功才绿灯。检票员看到所需字段，不能全名单导出、补录、增额、纠错或补发。找票辅助查找不等于验证持票人身份，不凭尾号直接发码。

每名额只核销一次，支持 3 人组先 2 后 1。无效票、已用尽、活动暂停、数量不足、未授权、请求未知分别处理。相同已成功请求重试返回原成功，不重复放行第二批；再次实际入场使用新的明确操作，仍检查余额。

原成功结果的补查/重放须显示原操作时间、人数及“这是原操作结果”的提示；已确认过的结果不再次触发新的放行声音或误导为新增一批。具体重放标志与页面状态在 D3/D4 对齐。

### 5.5 自助 kiosk

负责人授权终端并启用受限模式；参与者扫描本组码，输入/确认本次数量，成功后清屏。无搜索名单、手机号遍历、改名额或管理解锁入口；无效/异常转工作人员。管理解锁由负责人身份完成，清屏不撤销已提交事实；设备锁定与网页全屏分开验收。

### 5.6 现场负责人操作及纠错

正常公众变更在现场冻结；负责人走专用现场补录/加人流程，校验容量、理由与审计。名额分配不等于到场；需要入场时另做核销。若已存在待审核报名，现场处理要关联原申请及来源，不能无意创建重复组。

误检更正须关联原记录、理由及负责人，候选限制为累计更正不超过原记录人数且组净核销不小于 0；与同组后续核销并发时原子校验。更正用于纠正误操作，不记录离场、不提供再次入场业务。结束后普通核销/增额关闭；历史更正的特权窗口在 API 细化并留审计，不自动重开活动。

### 5.7 查询、统计、导出与交付

负责人列表可按活动、资格、来源、时间、是否有待增员、入场进度及通知状态筛选；检票员只在获授权活动做限量辅助查找；校方只读按授权活动/字段查看，个人私密入口只查本组。

统计分别显示申请组数、待审核组数、有效组数/人数、原核销、关联更正及净累计核销、剩余未用名额、现场补录/增额，标明时点。入场率的分母为当前有效已批准名额，零分母显示无数据，不把组数和人数混算。

导出格式为 CSV/XLSX，候选字段包括活动标识/名称、组标识、获准的姓名/手机/邮箱、来源、资格、已批准人数、待增员数、净核销及进度、报名与最近核销时间；来源内部秘密和票码/私密访问凭据不导出。字段按授权收缩，未收字段留空；明细查看不隐含导出。文件到期、下载和范围有记录，接收方/用途/字段及访问有效期在真实交付前落实，当前不自动向海外发邮件。

### 5.8 到期清理与凭证失效

明细按活动默认结束后 30 天可配置，服务端记录到期状态并实际清理受管明细、暂存、生成文件和端上必要数据，私密链接过期；备份恢复重新执行清理依据，不复活旧数据。只保留无个人标识且不可反查组的必要汇总；详细匿名化及备份轮换在技术规格定义。已下载文件、已投递邮件和原第三方数据由交付约定处置，系统不能远程保证删除。

## 6. 一致性、错误及安全要求

服务端验证活动/终端/账号/字段/动作，返回最小数据。组码仅用于核销，本组查询与变更需独立能力；秘密不入页面、导出、可分享 URL 或普通日志。错误不泄露其他活动资源存在性。

组人数、净核销、事件总占额和审核决定需明确事务与版本冲突，不靠前端预查询余额。导入、批准、核销、纠错、补发和通知分别有幂等及失败语义；邮件与第三方调用不放在持有名额锁的长事务里，任务失败保持可追溯状态。

网络中断、5xx、超时与确定的资格拒绝分开。未知结果不自动显示失败或成功；重试沿用原操作 ID。具体 ID 作用域、幂等保留期、请求载荷摘要与清理后行为在 D3 定义，独立契约门控结论见Gate1报告，不将本条当成运行验证。

## 7. 非功能与验收计划

首轮设备建议 Android 手机/平板浏览器及 Windows 浏览器；具体版本与扫码解码库在实现基线核实锁定。5 台同时争抢同组最后名额应只成功一次；500 人目标下评估表单、查找、扫码和统计，不以静态文档宣称吞吐/延迟实测通过。触控大按钮、明确文字、辅助声音及避免仅颜色反馈为交互要求。

| 编号 | 验收条件 |
|---|---|
| AC-01 | 随行缺省 0 形成 1 名额；同组 3 人按 2/1 分批，第三次超额拒绝 |
| AC-02 | 待审核不占额、不发有效票；两个批准请求争抢容量只在额度内生效 |
| AC-03 | 审核模式加 1 未通过前原名额可用，批准差额时再占 1，拒绝不减少原批准数 |
| AC-04 | 自助开关/截止/已核销限制生效，姓名/手机/邮箱可选规则与短信依赖一致 |
| AC-05 | 来源有效资格仍校验字段与容量，同源重传不新增，跨源疑似重复不静默合并 |
